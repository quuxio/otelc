# Invocation-scoped diagnostic witness: development contract

`scoped_action_v1` is unavailable in every language. The private Python wire codec, protocol state kernel and [shared record schema](schemas/witness-control-v1.schema.json) have framing and lifecycle model tests. Private source-manifest, ordinary-import bootstrap and monitoring/SDK components also have original-code and decoded-span tests, but no launcher accepts the mode and no producer control transport is installed. These components do not establish full application/dependency artifact provenance, transport sequencing, general quiescence or independent consumer acceptance. Existing oteleq name/process observations retain their declared limits.

The private code registry additionally fingerprints actual CPython 3.12/3.14 code objects with bounded, passive builtin metadata encoding. Weak registrations use object identity rather than code equality: a structurally equal clone has the same fingerprint but cannot satisfy the original registration. Unknown constants are refused without their representation, hash, equality or metaclass hooks. The fingerprint includes the concrete interpreter/bytecode profile and code metadata; it is not a substitute for source, dependency, selection or call-site provenance. No live envelope or SDK span is bound by this registry alone.

The private synchronous call-site binder checks registered caller/callee identities and a declared ordinary `CALL` offset without disassembling application constants. Actual monitoring callbacks qualify CPython 3.12's caller position after inline caches and 3.14's position at `CALL`. A signal callback sharing the same native thread and live envelope ancestor does not match the intended site; equal caller/callee code clones also fail. Other compiler versions, keyword-call and generator/coroutine profiles remain refused. This primitive does not establish live execution ownership by itself.

The private execution-owner component now supplies primary-entry and live envelope/wrapper generations in isolated original-code fixtures. It combines native-thread ownership, exact caller sites and live frame identities, without retaining frames or application code. Factories and another wrapper invocation cannot satisfy the intended target entry; direct target recursion remains observable. Normal returns and exception unwind retire ownership. Repeated primary/envelope entry, bounded activation exhaustion, early shutdown and missing child completions visibly invalidate it. This is still not a launcher integration or an available action-witness profile.

Behavioural tests use actual monitoring callbacks over unchanged fixture code. Separate direct API drivers exercise real frame/call-site/standard-loader relationships for coverage: CPython suspends the coverage tracer inside monitoring callbacks, and recursively enabling it stalled the test harness. No recursive tracing is installed in the producer. The coverage measurement does not replace the unchanged-code controls. Remaining production integration includes the common launcher/configuration surface, bounded transport, full artifact provenance and independent oteleq qualification. The synchronous profile must detect and refuse unsupported continuation creation and account for observed SDK leases; these owner primitives alone do not establish quiescence.

The private SDK bridge uses observed owner entries before normal function selection, admits the wrapper as an independent local SDK root, and emits consumed IDs from that actual admitted span. Only the intended wrapper and target recursion receive scope/probe attributes; a target reached through an argument factory remains untagged retained evidence. Trace-only resource metadata carries the runtime/build/selection identities, without adding diagnostic identities to metrics. Actual pending calls, leases, cumulative loss, queued trace export and reader completion determine provisional/final health. Normal/exception controls decode the SDK protobuf output; unsampled roots, capacity loss, unarmed calls, absent root admission, failures before the intended target and export failures cannot report complete. The original SDK unit controls use model build/selection digests; the source bootstrap tests below bind a real frozen source/compiler manifest. Neither establishes the still unsupported continuation boundary.

The private frozen program inventories at most 256 Python source files, 512 directories and 16 MiB of source under one fixed absolute root. Actual file reads are bounded; symlinks, special files and unreadable directories are refused. Manifest bytes are bounded to 256 KiB. It records source hashes and module/role compiler fingerprints, the exact qualified CALL sites, CPython version/cache/optimisation identity, the maintained adapter/requirements digest and common admission-policy identity. Ephemeral signal endpoints and resource values are excluded from the selection identity; queue bounds remain included. Rebuilding and comparing the record rejects changed source, compiler, selection or manifest fields. Existing annotation decisions and source/function exclusions retain their common-policy precedence.

The private bootstrap is supplied the real primary compiler object before execution, observes its actual entry/envelope, and captures imported module code only through the qualified standard SourceFileLoader and import bridge. It checks loader/module namespaces passively, retains no application frames and transfers the original live generations at rendezvous. It then activates the expected probe digests with actual registry handles and binds the SDK root. Both ordinary top-level and lazy imports have unchanged-source/output controls. Preloaded targets, replaced loader compiler methods, equal target-code clones, reloads and unsupported loader metadata cannot establish the scope. Final source validation also rejects changes after span admission. This relies on the standard loader methods present when bootstrap is imported, not a hostile-code containment boundary.

This initial private manifest supports ordinary top-level synchronous function roles and qualified positional CALL sites on CPython 3.12/3.14. It fixes the materialised source root: moving the source requires fresh launch bindings, while an independent consumer must preserve and revalidate the original frozen provider/data/artifact hashes. It inventories Python source and the adapter, not non-code inputs, native libraries or the full installed dependency graph. Broader build provenance, nested/class/keyword/async profiles, preloaded/custom loader integration and continuation creation still require implementation or separate qualification. No public capability is advertised by these components alone.

The private entry anchor now preserves observed primary/envelope generations while a profile waits for imported target code. Original-code fixtures qualify both top-level imports and lazy imports inside the envelope on CPython 3.12/3.14. A completed profile can adopt those same live generations at the actual envelope or rendezvous entry. An earlier unrelated rendezvous cannot consume them; repeated primary execution, duplicate transfer and closed entry windows are refused. No application frame is retained by either component. This primitive is not yet wired into the real launcher.

An actual import experiment also distinguishes the original SourceFileLoader execution, through CPython's import bridge, from directly executed module copies and cloned target code. All application results and source bytes remain unchanged. This is provenance evidence for the next production discovery component, not an installed import hook or a claim that custom loaders, preloaded modules or all import shapes are qualified. The diagnostic harness must retain its ordinary private-channel rendezvous barrier in both lanes; producer readiness does not replace the harness release schedule.

The intended contract binds an action to its actual compiler-identified rendezvous/wrapper/target, one live execution context and one fresh scope. Baseline and instrumented workers execute the same ordinary generated harness bytes and schedule without required application SDK imports. Argument factories, observers and result/error formatting stay outside the action wrapper. Display names and process nonces cannot establish attribution.

## First profile and bounds

The agreed first qualification profile is an ordinary synchronous Python function on one native execution thread. It requires a fresh process for each action/attempt, including replay/export/shrink trials. Ordered Node sequences retain their stateful worker and remain unavailable under this initial profile; splitting them into fresh processes would change their semantics. Async/task and other language profiles require separate implementations and independent qualification.

Consumption must match the live generated-envelope invocation and the exact compiled wrapper call site, including caller code and bytecode position. Matching a thread and wrapper name is insufficient: a same-thread signal handler or reentrant callback could otherwise consume the arm. The frozen manifest must bind the qualified interpreter/compiler form and rendezvous/envelope/wrapper/target/call-site identities. Model tests do not replace actual signal/callback controls through those compiler hooks. Reaching the intended call site before arm permanently invalidates the attempt instead of allowing a later arm to salvage it.

Producer control is private, owner-only and separate from harness release, application channels and OTLP. It accepts at most 16 request frames per runtime, including capabilities queries and invalid/duplicate requests. Duplicate-request history is consequently bounded. A scope can be armed once and permanently retired; consumed/cancelled scopes cannot be rearmed. The event buffer is bounded to 64 records, and overflow prevents success. The control service never executes arbitrary process commands or accepts executable paths.

One UTF-8 JSON object is followed by a single LF, with a maximum 16 KiB frame including the LF. CRLF, multiple frames, invalid UTF-8, duplicate keys, unknown fields and non-integer numeric tokens are refused. Sequence values are integer tokens in `1..9007199254740991`; boolean, float, non-finite and unsafe integer values are refused. Requests/responses carry `request_id`; unsolicited events carry `event_seq`. Unknown operations or untrustworthy request identities cannot receive an invented normal echo response: the producer must invalidate through its trusted event stream and refuse/terminate that control session.

Runtime/context/scope/request identities and OTLP trace IDs are nonzero 128-bit lower-case hexadecimal strings. Actual OTLP span IDs are nonzero 64-bit strings. Compiler/probe/build/selection digests use 256-bit lower-case hexadecimal strings. The schema rejects zero identity placeholders structurally; actual identity freshness and compiler/context binding still require semantic runtime and independent consumer checks.

## Required runtime lifecycle

1. The actual rendezvous control probe emits ready with runtime, compiler binding, context cookie and readiness sequence. Harness readiness is separate.
2. Arm validates those identities and the exact wrapper/target bindings before acknowledgement. The harness releases only after that acknowledgement.
3. Exactly one matching wrapper entry on the same live context consumes the arm and reports its actual SDK trace/span IDs. Unrelated calls on another thread cannot consume it.
4. Root exit reports the original outcome. An end event is provisional; it does not prove quiescence or completed export.
5. The producer continues observing scoped activity. Late activity after provisional end visibly invalidates the scope and cannot restore success.
6. Runtime end reports final inflight/pending/loss/export health after observer/export shutdown. The consumer drains until control EOF **and** application process completion, verifies sequence continuity and final clean health, and refuses missing or contradictory evidence. Export acknowledgement alone does not prove downstream storage.

Health separates active scoped execution (`inflight`), reserved continuations (`pending`), cumulative instrumentation/control/export losses (`losses`) and drained export/shutdown (`export_finished`). Pending export alone may finish after provisional end; it is not represented as a continuation. The initial synchronous profile refuses live executions/continuations or any reported loss at provisional end. A later zero snapshot cannot erase an earlier failure. Only final clean health after owner retirement permits the model to emit a successful runtime-end record; the real producer and independent consumer still have to establish those facts.

Decoded OTLP must join `otelc.probe.id`/`otelc.scope.id` span metadata and `otelc.runtime.instance`/`otelc.build.id`/`otelc.selection.id` resource metadata to the frozen manifest and control exchange. High-cardinality diagnostic identities do not belong in metric labels. Factories, observers, background calls and startup spans remain retained evidence but cannot satisfy the action witness.

Required controls include normal/exception/recursive targets, concurrent wrong-thread calls between arm/consume, target calls from observers/factories, stale/reused/cross-runtime identities, duplicate consume, missing/mismatched end, late descendants, cancelled/incomplete work and export loss. No fallback may silently weaken requested scoped attribution. The result remains equivalence over declared tests and observations; this protocol does not establish exhaustive inputs/schedules, complete hidden-state observation or hostile-code containment.
