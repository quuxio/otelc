# Java exception safety

<!-- markdownlint-disable MD013 -->

Instrumenting a function must not execute application exception getters or formatters. Even a standard `RuntimeException` can have a custom cause whose message getter changes application state. Catching failures from those getters does not undo their side effects.

otelc keeps the official Java agent, instrumenter, SDK and metrics customiser. Its small function probe module replaces the stock method advice. It disables automatic cause unwrapping and wraps only the method span's exception recording. An escaping error sets ERROR status and adds one `exception` event with `exception.type` obtained from the final JVM class identity operation. It does not call `getMessage`, `getLocalizedMessage`, `getCause`, `toString`, `getStackTrace` or `printStackTrace`. Messages and stack traces are deliberately unavailable; a wrapper is reported as the actual thrown wrapper type.

The exception passed to the application is unchanged. For declared `CompletionStage` return types, a small `handle` observer finishes the official instrumenter with the original error and resolves its discarded observer stage normally. An exceptionally completed `whenComplete`-derived stage can ask the JDK to format the original throwable; a successful observer result avoids that extra call. The application's original stage is returned unchanged. The span and admitted direct metrics complete when that stage completes, including exceptional completion before or after the method returns. Instrumentation failures remain suppressed inside the callback, rather than becoming another failed derived stage. Other return-type classifications and asynchronous strategies retain the official support implementation. Custom stage implementations, broad reactive-library and classloader qualification remain outstanding. This change does not claim automatic task-context propagation.

The active application context retains the original SDK span so synchronous children inherit the SDK's anchored clock. The exception-safe wrapper remains in the private context used to finish the official instrumenter. Deterministic tests move wall time forwards and backwards while monotonic time advances, then require actual exported child intervals to remain within their synchronous parent. Timestamps are not clamped or rewritten.

The completion regression requires zero formatter calls for a custom top-level runtime exception which throws if formatted, preserving both future and error identity. Separate cases cover already-failed and later-failed stages. The actual-agent test also repeats the direct-error case through every live metric state; an application-owned `handle` checks error identity without adding its own failed-stage formatting. The original nested-cause and synchronous getter regressions remain in place.

Advice uses the selected method's compiled descriptor, rather than reflecting over its declaring class. Only a non-null successful result needs its declared return type resolved for asynchronous strategy selection. Missing types on unrelated declarations or unused parameter types therefore do not prevent completion; the completion helper handles null results and escaping errors without return-type lookup. The pinned Byte Buddy transformer still requires metadata for a selected declaration's own return type. Bytecode-only preflight rejects that unsupported selection before application execution, including nullable and array returns.

The real-agent regression compares plain and instrumented source-free applications through six exception shapes, including nested custom causes, getters which throw, and a wrapper subclass overriding `getCause`. It preserves original source/class/tooling identities, stderr, synchronous throwable identity and future identity. In the same instrumented PID it tests all four live metric states, deferred completion, decoded ERROR events and final zero-active/zero-drop SDK evidence. The control using the stock method implementation fails because an application getter changes state.
